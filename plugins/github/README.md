# GitHub 仓库动态插件（cn.ucbk.github）

监控 GitHub 仓库的 Issue、PR、提交与 Release，有新动态就按 Diana 的样式推送到群聊或私聊；还能在 QQ 里直接给仓库提 Issue（先存草稿、确认后再提交）。

推送长这样：

```text
GitHub 动态: SuInk/Diana
Issue #1116（更新）
fix(rss): v0.8.151 中 X 订阅推送的配图全部丢失
作者：c837835323
更新于 2026-10-18 09:17:16
https://github.com/SuInk/Diana/issues/1116
```

## 能力与出网

| 项 | 内容 |
| --- | --- |
| 能力 | `msg.send`（中风险）、`http.outbound`（**高风险**）、`plugin.storage`（低风险） |
| 出网域名 | 仅 `api.github.com` |
| 依赖 | 无第三方库，只用宿主 SDK 与标准库 |

`http.outbound` 是高风险能力，**审核时必须由管理员在面板上单独勾选**；漏勾时插件能装，但轮询会暂停并只在日志里提醒，指令会回「GitHub 服务暂时不可用」。

## 目录结构

| 文件 | 职责 |
| --- | --- |
| `plugin.py` | 入口：收消息、找轮询器、分派指令 |
| `ghub/support.py` | 文本切分、发消息、打码等通用工具 |
| `ghub/auth.py` | 管理员、凭证、草稿的权限判断 |
| `ghub/settings.py` | 每仓库设置的展示与写入 |
| `ghub/commands.py` | 指令与设置值解析（含取值校验） |
| `ghub/store.py` | 状态文件读写、已见条目比对 |
| `ghub/client.py` | GitHub REST 客户端（含 Star 统计） |
| `ghub/formatter.py` | 推送消息拼装（含打码、Star 样式） |
| `ghub/drafts.py` | Issue 草稿状态机 |
| `ghub/poller.py` | 后台轮询 |
| `ghub/handlers_repo.py` | 仓库管理与配置指令 |
| `ghub/handlers_cred.py` | 凭证指令 |
| `ghub/handlers_issue.py` | Issue 与立即检查指令 |

单文件都在 500 行以内，按职责拆开，改动时只碰对应模块。

## 打包与安装

```bash
python plugins/pack.py github
# 生成 plugins/dist/cn.ucbk.github-1.1.0.zip
```

1. 插件市场 → 提交压缩包，上传上面的 zip；
2. 插件审核 → 审核通过（记得勾选 `http.outbound`）→ 上架；
3. 插件市场 → 安装，勾选生效机器人，**手动开启**（安装后默认停用）。

`plugin.storage` 只是声明用途（状态文件落在 `data/plugins/cn.ucbk.github/`），不勾也能跑，插件会自己建目录。

## 指令一览

默认前缀 `gh`，前缀后加不加空格都认（`gh帮助`、`gh 帮助`），前缀可在配置里改。

| 指令 | 说明 | 权限 |
| --- | --- | --- |
| `gh 帮助` | 列出全部指令 | 任何人 |
| `gh 仓库列表` | 查看已监控的仓库、推送目标数、管理员数 | 任何人 |
| `gh 添加仓库 owner/repo` | 监控仓库，当前会话自动成为推送目标；第一个添加者成为管理员 | 任何人 |
| `gh 删除仓库 owner/repo` | 停止监控并清掉该仓库的草稿 | 管理员 |
| `gh 添加管理 owner/repo QQ` | 添加管理员，多个 QQ 用逗号或空格隔开 | 管理员 |
| `gh 删除管理 owner/repo QQ` | 移除管理员，至少保留一名 | 管理员 |
| `gh 配置 owner/repo` | 查看该仓库的全部设置（分支、显示名、打码、周期、凭证、监控内容、通知、Issue 管理、Star 阈值） | 任何人 |
| `gh 设置 owner/repo 键=值 ...` | 修改该仓库的设置，多项用空格分隔；键可用中文（见下） | 管理员 |
| `gh 设置令牌 owner/repo 令牌` | 给单个仓库直接绑令牌（老办法，推荐改用「添加凭证」） | 管理员 |
| `gh 凭证列表` | 查看全局凭证（令牌只显示打码后的头尾） | 任何人 |
| `gh 添加凭证 名字 令牌` | 新增/覆盖一条全局凭证，例如 `gh 添加凭证 公共 ghp_xxx` | 仓库管理员或全局管理员 |
| `gh 删除凭证 名字` | 删除凭证，引用它的仓库自动改回全局令牌 | 仓库管理员或全局管理员 |
| `gh issue owner/repo 标题 \| 正文` | 存一条 Issue 草稿，返回 4 位草稿码（仓库需开启 Issue 管理） | 任何人 |
| `gh 确认 码` | 提交草稿到 GitHub，回复 Issue 链接 | 发起人或管理员 |
| `gh 撤销 码` | 放弃草稿 | 发起人或管理员 |
| `gh 修改 码 标题 \| 正文` | 改草稿内容，确认码不变 | 发起人或管理员 |
| `gh 还原 码` | 已过期/已撤销的草稿还原成待确认，**换一个新码** | 发起人或管理员 |
| `gh 删除草稿 码` | 删除草稿记录（已写进 GitHub 的 Issue 不受影响） | 发起人或管理员 |
| `gh 草稿列表` | 看自己的草稿；管理员额外看到所管仓库的草稿 | 任何人 |
| `gh 检查` | 立即拉取一次动态，30 秒内不可重复 | 任何人 |

`owner/repo` 支持直接贴网址（`https://github.com/SuInk/Diana`），大小写不敏感；添加时会用 `GET /repos/{owner}/{repo}` 验证仓库真实存在，并采用 GitHub 返回的规范大小写。

## 每仓库设置（替代 Diana 的「仓库管理」面板）

宿主插件面板只能渲染 5 种标量字段、一张扁平表单，放不下「仓库列表 + 每行独立配置」，所以每仓库设置放在状态文件里、用指令改：

```text
gh 设置 SuInk/Diana 分支=main 打码=on 监控=issue,pr,commit 周期=3600 通知=on
```

| 键 | 取值 | 说明 |
| --- | --- | --- |
| `分支` | 分支名 / `默认` | 只管提交（commits）走哪个分支，留空用默认分支 |
| `显示名` | ≤40 字 / 空 | 推送首行的仓库名；空=仓库原名 |
| `打码` | `on`/`off` | 打开后不输出链接、作者名只留首尾（前 2 后 2），首行显示「某仓库」或显示名 |
| `周期` | 秒数 / `0` | 每仓库最短检查间隔，0=跟随全局；不能小于全局间隔（全局是节拍） |
| `凭证` | 凭证名 / `全局` | 该仓库用哪条凭证，空=插件配置里的全局令牌 |
| `监控` | `issue,pr,commit,release,star` / `全部` / `无` | 只拉需要的接口，省限额 |
| `通知` | `on`/`off` | 关掉后仍然检查并更新基线，只是不发消息 |
| `issue管理` | `on`/`off` | 关掉后该仓库不能起草 Issue |
| `星标阈值` | 1–100000 | Star 累计新增达到这个数才通知 |

`gh 配置 owner/repo` 会把这些项一次性列出来，效果等同于 Diana 面板里那一屏。后开启的监控类型（比如从没开过 Release 到打开）**先建基线再推送**，不会把历史动态当新消息刷出来。

> 多项设置用空格分隔；显示名里不要带空格（会被当成下一项设置）。监控列表用英文逗号。

## 配置项

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| 全局 GitHub 令牌 | 空 | **强烈建议填写**。不填时每小时只能拉约 60 次接口（约 5 个仓库），填了提升到 5000 次/小时；私有仓库与提 Issue 也必须配令牌（全局或仓库专属二选一） |
| 是否推送仓库动态 | 开 | 关掉后只记录日志、不往会话里发消息 |
| 轮询间隔 | 5 分钟 | 1 分钟到 24 小时；0 或留空按 5 分钟 |
| 每类保留条目数 | 10 | 每个仓库的 Issue/PR/提交/Release 各保留多少条已见记录，1 到 50 |
| 单次请求超时 | 20 秒 | 宿主侧封顶 30 秒 |
| 失败告警阈值 | 5 | 连续失败多少次给订阅会话发一次告警，0 表示不告警 |
| 发送失败告警 | 开 | 关掉后只在日志里留痕，不在会话里提示 |
| 推送说明 | 空 | 填了就在每条动态推送前加一句，留空不加 |
| 指令前缀 | gh | 改后缀，比如 `git` |
| 全局管理员 QQ | 空 | 多个用逗号分隔，视作所有仓库的管理员 |

配置改完**下一条消息生效**：宿主只在转发事件时附带配置快照，轮询器每条消息刷新一次。

## 轮询与推送规则

1. 插件子进程没有启动钩子，轮询任务**懒启动**：机器人发出/收到的第一条消息就会唤醒，之后常驻；
2. 首个轮询周期只建基线不推送，避免把历史动态当新闻刷屏；后开启的监控类型单独建基线；
3. 之后每轮按仓库「监控内容」拉对应接口，与已见记录比对：新条目推「新建」、更新时间变了推「更新」、Issue 关了推「关闭」、重开推「重新打开」、PR 合并推「合并」、新提交推「推送」、新 Release 推「发布」；
4. Star 只在累计新增达到阈值时推一条（负增长不计入，阈值内先攒着）；
5. 单次轮询每个仓库最多推 10 条，条目之间隔 0.5 秒、仓库之间隔 0.4 秒，避免被 QQ 侧限流；
6. 连续失败达到阈值才告警一次，恢复后自动复位；期间只写日志，不刷屏；
7. 时间一律换算成北京时间（UTC+8），与运行机器时区无关。

推送长这样（开了打码时链接会去掉、作者名只留首尾）：

```text
GitHub 动态: SuInk/Diana
Star 1213（+3）
累计新增 3 个 Star，当前共 1213 个
https://github.com/SuInk/Diana/stargazers
```

## Issue 草稿

```text
gh issue SuInk/Diana 反馈 | 这里是详细描述
```

只存草稿不提交，回复一个 4 位码；`gh 确认 码` 才真正 `POST /repos/{owner}/{repo}/issues`。草稿 7 天不确认自动过期，过期/已提交/已撤销的记录保留 30 天后清理，全程只动本地状态文件。过期或撤销后想继续写，用 `gh 还原 码`（会换一个新码，旧码作废）；`gh 修改 码` 可以直接改标题正文；`gh 删除草稿 码` 只删本地记录，GitHub 上的 Issue 不受影响。确认时需要令牌具备该仓库的写权限（`public_repo` 或 `repo` scope），否则回「提交失败」并保留草稿可重试。

## 状态文件

每个机器人一个 JSON：`data/plugins/cn.ucbk.github/state-{机器人QQ}.json`，由插件包位置向上推导，升级换包后不丢数据。内容是监控仓库（推送目标、管理员、每仓库设置、凭证名、已见条目、Star 计数、失败计数）、全局凭证表与 Issue 草稿。写入走「临时文件 + 原子替换」；「读 -> 改 -> 写」全部在锁内完成，与后台轮询互不覆盖。凭证以明文存在状态文件里（和 Diana 后台的做法一致），服务器上注意该目录的访问权限。

## 与 Diana 面板的差距（同功能、不同载体）

宿主插件的配置弹窗只支持 `text/password/number/switch/select` 五种标量字段，渲染成一张扁平表单（`plugin_manifest.ALLOWED_CONFIG_TYPES` + `PluginInstalledPage.vue` 的 `v-for`），没有表格、多标签页和自定义页面。所以：

| Diana 的界面 | 这里怎么办 |
| --- | --- |
| 仓库管理表格（每行调分支/打码/周期/凭证/监控内容） | `gh 配置 owner/repo` 看、`gh 设置 owner/repo 键=值` 改 |
| 凭证管理（多条 + 检测账号） | `gh 添加凭证` / `gh 凭证列表` / `gh 删除凭证`（没有「检测账号」，用 `gh 添加仓库` 时顺带验证） |
| 运行记录里的草稿管理（直接提交/修改/还原/删除） | `gh 确认/修改/还原/删除草稿/草稿列表` 五条指令 |
| 执行日志页 | 看宿主的插件日志（同一条链路） |
| 颜色状态（PR/Issue/Release 配色） | QQ 纯文本没有配色，用「（新建/更新/关闭/合并/发布）」文案区分 |
| 机器人跟评（LLM） | 不做：`llm.generate` 只有能力声明、无运行时实现 |
| 推送模板占位符 | 不做：只有「推送说明」前缀一句 |

## 已知限制

- **没有实现机器人评审**：宿主的 `llm.generate` 能力只有白名单声明、无运行时实现，插件不依赖它，推送后不会接 AI 点评；
- **没有实现推送模板自定义**：消息格式固定成 Diana 的默认样式，只有「推送说明」可以在前面加一句；
- 请求超时上限 30 秒（宿主硬限制），Diana 面板上的 90 秒在这里配不出来；
- 每仓库检查周期不能小于全局轮询间隔（全局是节拍器）；
- 无令牌时 GitHub 限额约 60 次/小时：开了 Star 监控每个仓库每轮要多花 1 次请求，仓库多时请填令牌；
- 每条 GitHub 接口响应按 20 万字符截取，超长正文可能取不到（会记失败并告警）；
- 配置改动要下一条消息才生效（宿主只在事件里带配置快照）；
- 群成员都可以 `gh issue`，真正的提交门槛在确认步骤、`issue管理` 开关和令牌权限上。

## 约定

- 出网一律走 `host.http_request`，域名受清单白名单约束，换接口必须同步改 `allowed_domains`；
- 事件处理函数只解析指令和改本地状态，重活（轮询、提交 Issue）全部放后台任务：宿主对单个事件有 10 秒超时，超时会杀掉插件子进程；
- 任何失败都回中文提示，不向宿主抛裸异常；
- 不直接调用 OneBot，发消息一律通过 host 完成。
